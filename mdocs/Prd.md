## 1. 背景与目标

### 1.1 问题背景

主流播客客户端（Apple Podcasts、Spotify、小宇宙等）普遍要求账号登录、依赖厂商云端同步订阅与播放数据，用户对自己的订阅关系、收听记录、下载内容缺乏完全控制权；同时几乎没有严肃对待**桌面端**场景的播客客户端——多数产品以移动端为核心、桌面端是移动端的阉割版或干脆没有。

对于希望**数据完全留在本机、不被任何厂商账号绑定、不依赖网络也能听、且主要在电脑前工作/生活**的用户，市面上缺乏一款专注桌面、离线优先、本地优先的播客客户端。

### 1.2 产品目标

做一款**不依赖任何自建服务端**的跨平台桌面播客客户端：

- 用户输入 RSS 地址即可订阅，播放、下载、笔记、播放进度等全部数据**只存在用户本机**；
- 断网状态下，订阅浏览、已下载内容播放、历史数据查看、笔记记录等核心体验**不受影响**；
- 不强制账号登录，不存在“服务端下线导致客户端不可用”的风险；
- 覆盖 Windows / macOS / Linux 三大桌面平台，交互体验貼合各平台原生习惯。

### 1.3 “不依赖服务端”的准确定义

本产品**不自建、不运营任何后端服务**（无账号系统、无用户数据云端存储、无自有 API 网关）。但以下两类"网络请求"是被允许的，且不违背 Local-first / Offline-first 原则，需在本 PRD 中明确边界：

1. **直连第三方数据源**：客户端直接向用户填写的 RSS Feed URL、公开播客目录 API（如 Apple Podcasts 搜索接口、Podcast Index）发起请求，请求方与响应方之间没有产品自建的中间层。这类请求失败不影响已缓存/已下载内容的可用性。
2. **通用基础设施**：应用自动更新（`electron-updater` + 通用文件服务器）、可选的用户自选云盘同步（OneDrive/Google Drive 等，用户自己的账号）。这些均为**非核心、可关闭、失败不阻塞主流程**的能力。

> 判定标准：任意功能一旦断网或第三方源不可用，应**优雅降级**为"仅用本机数据可用的能力子集"，而不是整体不可用。

### 1.4 非目标（Out of Scope）

- 不做移动端（Android / iOS）、不做浏览器 Web 端；
- 不做账号体系、不做社交关系（关注其他用户、评论区）；
- 不做播客创作/发布/RSS 生成功能（本产品是播客客户端，非播客制作工具）；
- 不做付费订阅内容的 DRM/解密支持；
- 不承诺对内容分发平台的收录审核（内容合规由 Feed 提供方负责）。

## 2. 目标用户与场景

### 2.1 用户画像

| 画像 | 特征 | 核心诉求 |
|---|---|---|
| 深度播客听众 | 订阅数十个播客，每天固定时段收听，长期积累收听历史 | 数据不丢失、可迁移、可备份 |
| 隐私敏感用户 | 不希望个人收听偏好被厂商采集用于推荐/广告 | 本地存储、可关闭日志、隐身模式 |
| 弱网/无网环境用户 | 出差、通勤地铁、跨境网络受限地区 | 提前下载、离线播放稳定可靠 |
| 效率工作者 | 播客当背景音，需要键盘操作、系统级媒体键、变速播放 | 全局快捷键、系统媒体控件集成 |
| 多设备用户（次要） | 台式机 + 笔记本切换使用 | 可选的自建同步盘备份/还原 |

### 2.2 典型场景（User Journeys）

1. **首次使用**：用户打开应用 → 从别处拿到一个 RSS 链接粘贴进去 → 秒级看到播客信息与集数列表 → 点击播放，无需注册登录。
2. **迁移场景**：用户从其他播客 App 导出 OPML → 批量导入 → 保留原有订阅结构（分类/文件夹）。
3. **断网通勤**：用户在地铁上打开应用，Wi-Fi 已断 → 之前下载的集数可直接播放，进度记忆正常，未下载内容显示"仅元数据，可预约下载"提示，不报错、不空白。
4. **数据搬家**：用户更换电脑 → 导出完整本地数据（单文件）→ 新电脑导入 → 订阅、播放进度、下载记录（如已重新下载）、笔记均恢复。
5. **专注收听**：用户切到其他应用工作，用系统媒体键（键盘/耳机）控制播放/暂停/切集，无需切回播客窗口。
6. **数据清理**：用户存储空间紧张 → 查看播客/播放列表维度的下载占用 → 按策略批量清理旧下载，订阅与元数据保留。

## 3. 设计原则（贯穿全部需求的约束）

以下四条原则对每一条功能需求都构成硬性验收标准，评审与测试时需逐条对照：

| 原则 | 定义 | 验收角度 |
|---|---|---|
| **Feature-first** | 以用户场景驱动功能拆分，每个功能模块独立可交付、可测试，代码组织按功能域而非技术层 | 每个功能可单独发布、单独回归测试，不与其他功能强耦合 |
| **Offline-first** | 所有核心功能在离线状态下可用，网络仅用于"发现新内容"和"同步更新"这类锦上添花的能力 | 断网测试：核心用户旅程（浏览已订阅、播放已下载、记笔记、管理播放列表）100% 可用 |
| **Local-first** | 数据默认且优先存储在本机，用户完全拥有自己的订阅、播放记录、下载内容、笔记 | 卸载应用前可完整导出数据；无强制登录；无强制云同步 |
| **Desktop-only** | 仅面向桌面操作系统（Win/macOS/Linux），交互遵循桌面范式（窗口、菜单栏、快捷键、托盘） | 不做移动端适配，UI 基线为鼠标+键盘，而非触屏 |

## 4. 术语表

| 术语 | 定义 |
|---|---|
| Feed / RSS 源 | 播客的 RSS/Atom 订阅地址，产品的唯一内容入口，无中心化目录依赖 |
| OPML | 一种 XML 格式，用于批量描述订阅列表，是播客客户端间迁移订阅的事实标准 |
| Episode（集数） | 一个播客节目下的单条音频内容条目 |
| 已听 / 未听 | 集数的收听状态标记，非“是否下载” |
| 下载任务 | 将某集数音频文件持久化到本机磁盘的异步任务，具备排队、暂停、续传等生命周期 |
| Local-first 数据域 | 订阅关系、播放进度、已听状态、下载记录、播放列表、笔记、应用设置 — 这些数据永久落地本机数据库/文件系统 |
| 隐身收听模式 | 临时关闭播放历史/进度记录的收听状态 |
| 主进程 / 渲染进程 / Preload | Electron 三层架构角色，详见第 9 章 |

## 5. 范围与阶段划分（Scope & Milestones）

考虑到功能清单条目繁多，PRD 按 **P0（MVP）/ P1（正式版）/ P2（增强）** 划分优先级，确保先交付一个"离线优先、数据本地"的最小闭环，再逐步叠加体验优化。判定优先级的核心依据：**是否位于"添加订阅 → 浏览 → 播放 → 离线可用 → 数据不丢"这条主链路上**。

### 5.1 P0（MVP，必须优先交付）

覆盖第 1/3/4/5 章（订阅管理、音频播放、离线下载、本地数据）中的基础项，以及第 11 章中影响数据安全的错误恢复能力：

- RSS 订阅添加、解析、去重
- 订阅列表基础展示（排序、搜索）
- 播客详情页、集数列表（含已听/已下载状态）
- 播放器核心能力：播放/暂停/上下集/进度拖拽/时间显示
- 单集下载、下载队列基础管理（暂停/继续/取消）
- 已下载内容离线播放
- 本地数据库：订阅、播放进度、已听状态、下载记录持久化
- App 重启恢复播放进度、下载断点续传
- 窗口基础能力：单实例锁定、窗口状态记忆、原生菜单
- 完整本地数据导出/导入（JSON），保障"数据不锁死"
- 渲染进程安全基线、代码签名（发布前置条件，非功能性但阻断发布）

### 5.2 P1（正式版，紧随 MVP）

- OPML 批量导入导出
- 播放列表（创建/编辑/拖拽排序/队列）
- 变速播放、睡眠定时器、播放队列持久化
- 下载质量设置、存储空间管理、自动清理策略
- 深色模式、字体调节、播放器布局偏好
- 时间戳笔记
- 系统托盘、系统通知、后台播放媒体控件集成（SMTC/MPRIS/Now Playing）
- 全局快捷键、深链接协议
- 应用内自动更新
- 多语言（中/英）
- 错误恢复完善：Feed 拉取失败分类提示、下载失败重试、文件丢失检测、数据库自愈
- 诊断日志（可关闭）

### 5.3 P2（增强，视资源与用户反馈排期）

- 播客搜索目录集成（依赖第三方在线 API，纯增强，断网/无 Key 时不影响核心功能）
- 可选云盘同步（OneDrive / Google Drive，用户自有账号）
- 隐身收听模式
- 无障碍深化（屏幕阅读器、键盘全操作覆盖）
- 跳过静音片段
- 蓝牙/耳机媒体键控制
- 内容搜索（已下载/已订阅集数全文搜索）

> 完整条目级对照表见 `Feature.md`；本 PRD 不逐条复述勾选框，而是在第 6 章按用户故事组织需求，并标注对应优先级与验收标准。

## 6. 功能需求（Functional Requirements）

> 每节包含：用户故事、功能描述、验收标准（AC）、优先级。AC 使用 Given/When/Then 简化表达，供 QA 直接转测试用例。

### 6.1 订阅管理

**用户故事**：作为用户，我希望通过 RSS 地址或 OPML 文件快速建立我的订阅关系，并对其进行整理和维护，而不需要登录任何账号。

| 需求点 | 描述 | 优先级 |
|---|---|---|
| 添加订阅 | 输入 Feed URL，应用请求并解析该地址，展示标题/封面/作者/描述供确认后保存 | P0 |
| Feed 解析容错 | 解析失败（网络超时、XML 格式错误、编码异常）时给出具体原因，不写入脏数据 | P0 |
| 重复订阅检测 | 同一 Feed URL（忽略末尾斜杠/大小写差异）重复添加时提示已订阅，不产生重复记录 | P0 |
| OPML 导入 | 支持标准 OPML 1.0/2.0 文件批量导入，保留原文件的分组结构（若有），逐条失败不影响其余条目导入 | P1 |
| OPML 导出 | 导出当前全部订阅（含分类结构）为标准 OPML，可被其他播客客户端识别 | P1 |
| 订阅列表排序/搜索 | 支持按最近更新、名称、订阅时间、未听数量排序；支持标题关键词搜索 | P0（排序基础）/ P1（多维排序） |
| 分类/文件夹 | 用户可自定义分类，将播客归入分类，支持多分类归属或单分类归属（需在设计阶段定案） | P1 |
| 取消订阅 | 取消后询问是否保留已下载文件和历史数据，默认保留（符合 Local-first） | P0 |
| 暂停订阅 | 暂停后不再自动拉取更新，但保留历史数据和下载文件，可随时恢复 | P1 |
| 刷新策略 | 手动刷新单个/全部；支持设置自动刷新间隔（如 30min/1h/6h/手动） | P0（手动）/ P1（自动间隔） |
| 新集数通知 | 新增集数后触发系统通知（可在设置中关闭） | P1 |

**验收标准示例**：
- Given 用户输入一个有效 RSS URL，When 点击添加，Then 5 秒内（正常网络）展示解析结果或明确的失败原因。
- Given 应用处于断网状态，When 用户尝试添加新订阅，Then 提示"当前无网络，无法添加新订阅"，且不影响查看现有订阅列表。

### 6.2 播客内容浏览

**用户故事**：作为用户，我希望清晰地看到每个播客的详情与集数列表，快速判断哪些内容已经听过、已经下载。

| 需求点 | 描述 | 优先级 |
|---|---|---|
| 播客详情页 | 展示简介、封面、作者、未听集数计数；支持"标记全部为已读" | P0 |
| 集数列表 | 标题、发布日期、时长、大小、已听/未听、已下载/未下载状态一目了然 | P0 |
| 历史集数加载 | 滚动到底部按需加载更早的历史集数（避免一次性拉取全部导致卡顿） | P1 |
| 集数详情 | 完整描述（支持 HTML 富文本渲染，需做 XSS 净化）、章节时间轴（如 Feed 提供 `<podcast:chapters>` 或 PSC 标签） | P1 |
| 添加到播放列表 | 从集数详情或列表直接加入指定播放列表或播放队列 | P1 |
| 分享集数 | 复制集数链接/Feed 原文链接到剪贴板（Electron 无跨平台原生分享面板，做降级方案） | P2 |

### 6.3 音频播放

**用户故事**：作为用户，我希望播放体验流畅、可控，并且能像系统原生媒体一样被系统媒体键、任务栏、通知中心感知与控制。

| 需求点 | 描述 | 优先级 |
|---|---|---|
| 播放器基础操作 | 播放/暂停、上一集/下一集、进度拖拽、当前时间与总时长显示 | P0 |
| 迷你播放器 + 全屏播放器 | 两种视图切换，进度/状态实时同步 | P0 |
| 系统媒体控件集成 | Windows SMTC、macOS Now Playing (MPRemoteCommandCenter)、Linux MPRIS，三端独立验收 | P1 |
| 系统托盘控制 | 托盘图标右键菜单可播放/暂停/切集，托盘图标状态反映播放态 | P1 |
| 变速播放 | 0.5x～3.0x，步长可配置（如 0.1x），记住上次选择 | P1 |
| 睡眠定时器 | 10s/30s/1m/5m/15m/30m/60m 倒计时后自动暂停 | P1 |
| 播放队列 | 独立于播放列表的"当前播放序列"，支持单曲循环/列表循环/随机播放 | P1 |
| 键盘快捷键 | 全屏播放器下方向键调整进度、空格键播放暂停等 | P1 |
| 跳过静音片段 | 基于音量阈值自动检测并跳过静音区间，可关闭 | P2 |
| 蓝牙/耳机媒体键 | 依赖系统媒体会话 API，与"系统媒体控件集成"共用底层实现 | P2 |

**关键非功能约束**：播放操作（暂停/跳转）延迟应 < 200ms；进度条拖拽期间不应产生音频卡顿或重复播放。

### 6.4 离线下载

**用户故事**：作为用户，我希望提前下载想听的内容，在没有网络时依然能稳定播放，并清楚知道下载占用了多少空间。

| 需求点 | 描述 | 优先级 |
|---|---|---|
| 单集/整栏/播放列表下载 | 三种下载触发入口，均进入统一下载队列 | P0（单集）/ P1（整栏、播放列表批量） |
| 下载队列管理 | 并发数可配置，支持暂停/继续/取消单个或全部任务 | P0 |
| 下载限速 | 可配置最大下载速度，避免占满带宽影响其他应用 | P2 |
| 下载完成自动播放 | 可选开关，下载完成后自动开始播放该集 | P2 |
| 存储占用展示 | 按播客/播放列表维度展示已下载内容占用空间 | P1 |
| 下载质量设置 | 若 Feed 提供多码率/多格式选项，允许用户选择标准/高/原声 | P1 |
| 自动清理策略 | 保留最近 N 天或 N 集，超出自动清理最旧的已下载且已听内容 | P1 |
| 存储空间预警 | 磁盘剩余空间低于阈值时提前提醒，避免下载中途失败 | P1 |
| 断点续传 | App 重启后自动恢复未完成的下载任务，从断点继续而非重新下载 | P0 |
| 完整性校验 | 下载完成后校验文件大小/校验和，损坏文件不进入"已下载"状态 | P1 |

### 6.5 本地数据（Local-first 核心）

**用户故事**：作为用户，我的所有数据都应该在本机可查、可控、可迁移，不因换设备、卸载重装、厂商停服而丢失。

| 需求点 | 描述 | 优先级 |
|---|---|---|
| 本地数据库 | SQLite 落地订阅、集数元数据、播放进度、已听状态、播放列表、笔记 | P0 |
| 完整数据导出 | 单文件导出全部本地数据（不含已下载音频文件本身，音频文件路径需可选择是否随备份记录） | P0 |
| 完整数据导入 | 导入前预览将产生的新增/冲突项，支持合并或覆盖策略 | P1 |
| 手动备份/恢复 | 用户可将数据库文件备份到自选位置，随时恢复到该备份点 | P1 |
| 数据库迁移 | 应用升级引发的 schema 变更需自动迁移；迁移失败时回滚并保留旧库文件，不得静默丢数据 | P0 |
| 云同步（可选） | 通过用户自有云盘（OneDrive/Google Drive/本地同步文件夹）实现多设备数据同步，默认关闭，失败不影响本机使用 | P2 |

## 7. 非功能需求（Non-Functional Requirements）

### 7.1 性能

- 冷启动时间（本机数据量 < 500 播客/10 万集）：≤ 3 秒进入可交互状态；
- 订阅列表滚动、集数列表滚动：60fps，不因数据量增大出现明显卡顿（虚拟列表/分页加载）；
- 播放操作响应：暂停/跳转 < 200ms；
- 下载并发对 UI 主线程无阻塞（下载在独立进程/线程执行，不影响播放与交互）。

### 7.2 可靠性

- 任何一次崩溃不应导致本地数据库损坏；写操作需具备事务性；
- 断电/强制退出后重启，播放进度丢失范围 ≤ 最近 5 秒（依赖定期落盘间隔的设计取舍）；
- 下载任务在异常退出后可续传，不产生重复文件或占用泄漏。

### 7.3 安全与隐私

- 默认不上传任何用户数据到产品方服务器（因为没有产品方服务器）；
- 私有/付费 RSS 凭据、可选云备份凭据本地加密存储（如使用系统 Keychain/Credential Manager/libsecret）；
- 渲染进程强制 `contextIsolation: true`、禁用 `nodeIntegration`、启用 `sandbox`，设置合理 CSP；此为发布阻断项；
- 富文本渲染（集数描述 HTML）必须做 XSS 净化，不允许执行远程脚本。

### 7.4 兼容性

- Windows 10 21H2 及以上、macOS 12 Monterey 及以上、Ubuntu 20.04 及以上（或等效 glibc 版本）；
- 安装包体积、依赖的原生模块需在三端 CI 分别构建验证。

### 7.5 可维护性与可测试性

- 遵循 Feature-first 目录组织，每个功能域（订阅、播放、下载、笔记……）代码与测试就近存放；
- 主进程与渲染进程通过 IPC 契约通信，契约需有类型定义（TypeScript）并可单独进行契约测试；
- 关键数据迁移逻辑需有针对旧版本数据库快照的迁移测试。

## 8. 数据模型（概念级，非最终 Schema）

用于评审阶段对齐数据边界，非数据库设计文档，后续由技术方案细化字段与索引。

```
Podcast（播客）
├─ id, feedUrl, title, description, coverUrl, author, language
├─ category（用户自定义分类，可多对多）
├─ subscribedAt, isPaused, lastFetchedAt, lastFetchStatus

Episode（集数）
├─ id, podcastId, title, description(HTML), publishedAt
├─ audioUrl, duration, fileSize
├─ isPlayed, playbackPositionSec
├─ isDownloaded, localFilePath, downloadStatus, downloadedAt
├─ chapters[]（可选，来自 Feed）

Playlist（播放列表）
├─ id, name, createdAt
├─ items[]（episodeId 有序列表）

PlaybackQueue（当前播放队列，与 Playlist 独立）
├─ items[]（episodeId 有序列表）, currentIndex, playbackMode（循环/随机）

Note（笔记）
├─ id, episodeId, timestampSec, content, createdAt

DownloadTask（下载任务）
├─ id, episodeId, status（排队/下载中/暂停/完成/失败）
├─ progressBytes, totalBytes, retryCount

AppSettings（应用设置，单例）
├─ defaultDownloadQuality, autoDownloadPolicy, refreshIntervalMin
├─ theme, language, playbackRateDefault, notificationPrefs
├─ incognitoMode, diagnosticsLogEnabled
```

> 数据迁移原则：任何新增字段需提供默认值与向后兼容的迁移脚本；破坏性变更需先在测试库验证回滚路径。

## 9. 系统架构概览

### 9.1 进程模型（Electron 三层）

```
┌─────────────────────────┐        IPC (契约化、类型化)        ┌──────────────────────────┐
│      渲染进程 (React)     │ <──────────────────────────────> │        主进程 (Node)       │
│  - UI / 状态管理           │                                  │  - 窗口/托盘/菜单/快捷键     │
│  - 不直接访问文件系统/网络   │      Preload 暴露最小 API 白名单   │  - SQLite 数据访问层        │
│                          │ <──────────────────────────────> │  - 下载队列 / 文件系统       │
└─────────────────────────┘                                   │  - Feed 请求 / RSS 解析     │
                                                                │  - 系统媒体会话集成         │
                                                                └──────────────────────────┘
```

- 渲染进程只负责 UI 呈现与用户交互，所有数据读写、网络请求、文件系统操作经由主进程完成，通过 Preload 暴露的受限 API 通信；
- 遵循 Repository 模式：主进程内部对 SQLite/文件系统的访问被封装为 Repository 层，渲染进程不感知具体存储实现，便于未来更换存储方案；
- 下载队列作为主进程内的独立子系统运行，与播放、UI 渲染解耦，避免相互阻塞。

### 9.2 关键流程（时序描述）

**添加订阅流程**：
1. 渲染进程发起 `subscribe(feedUrl)` IPC 调用；
2. 主进程请求该 URL，解析 RSS/Atom，提取播客与集数元数据；
3. 主进程写入本地数据库，返回结果给渲染进程；
4. 若请求失败（网络/解析错误），主进程返回结构化错误码，渲染进程据此展示具体提示，不写入任何数据。

**下载流程**：
1. 用户触发下载 → 主进程下载队列接收任务并入队；
2. 队列按配置的并发数调度，写入临时文件，完成后原子性移动为最终文件并更新数据库状态；
3. App 关闭时记录未完成任务的已下载字节数；重启后自动续传（HTTP Range 请求，若服务端不支持则重新下载并提示）。

**离线降级流程**：
1. 主进程维护网络状态感知（Electron `net` 模块 / 系统网络事件）；
2. 网络状态变化时通过 IPC 广播给渲染进程，驱动 UI 展示离线/弱网提示；
3. 离线期间用户的"标记已听""写笔记""调整播放列表"等操作正常写本地库，并进入"待同步操作队列"（如涉及未来的可选云同步），恢复网络后自动处理，纯本地操作无需队列即时生效。

**应用更新流程**：
1. `electron-updater` 定期或手动检查更新 manifest；
2. 发现新版本后下载安装包，Windows 静默下载完成后提示重启安装，macOS 下载完成后需用户确认重启；
3. 更新失败（网络中断、签名校验失败）分别提示并允许重试，不影响当前版本继续使用。

## 10. 平台差异与实现要点

| 能力 | Windows | macOS | Linux |
|---|---|---|---|
| 系统媒体控件 | SMTC | Now Playing / MPRemoteCommandCenter | MPRIS (`org.mpris.MediaPlayer2`) |

## 11. 发布与更新策略

- 版本号遵循语义化版本（SemVer），`package.json` 当前为 `1.0.0` 起点；
- 每个正式版本需三端构建产物均通过基础验收（安装、启动、核心播放/下载链路）才可发布；
- 更新走 `electron-builder` 的 `publish: generic` 通道，指向自建的静态文件托管（非应用服务端，纯文件分发，不违背"不依赖服务端"原则——它不承载任何用户数据，仅托管安装包与更新元数据）；
- 提供"稳定版/测试版"双渠道供愿意尝鲜的用户选择（P2，视团队资源排期）。

## 12. 验收标准与测试策略

### 12.1 三大原则的专项测试

| 原则 | 测试方式 |
|---|---|
| Offline-first | 完整断网环境下执行核心用户旅程（订阅浏览、已下载内容播放、笔记、播放列表管理），要求零报错、零白屏 |
| Local-first | 卸载前导出数据 → 全新环境重装 → 导入 → 逐项核对订阅/进度/笔记/下载记录是否完整还原 |
| Feature-first | 代码评审时检查功能模块间是否存在不合理的强耦合（如播放模块直接操作下载模块内部状态） |
| Desktop-only | UI 走查确认无触屏专属交互假设（如仅靠手势才能触发的操作），核心操作均有鼠标+键盘路径 |

### 12.2 关键场景测试清单（节选）

- 添加一个格式错误的 RSS URL，验证错误提示准确且不产生脏数据；
- 下载中途断网，验证任务进入"失败/待重试"而非无限转圈；
- 下载中途强制关闭应用，重启后验证任务自动续传而非从零开始；
- 数据库文件被外部程序损坏后启动应用，验证触发自愈流程或明确提示用户从备份恢复，而非崩溃退出；
- 三平台分别验证系统媒体控件、深链接协议注册是否生效。

## 13. 风险与依赖

| 风险/依赖 | 说明 | 应对策略 |
|---|---|---|
| 第三方 RSS Feed 质量参差 | 部分 Feed 格式不规范（缺失字段、非标准编码） | 解析层做宽松容错与字段兜底，记录解析日志辅助排查 |

| 系统媒体会话 API 的平台差异与原生模块维护成本 | Electron 对 SMTC/MPRIS 的官方支持有限，可能需引入原生绑定或第三方包 | 提前做平台能力验证 Spike，评估是否需要自研原生模块 |

## 14. 开放问题（待评审确认）

1. 分类/文件夹归属：播客是否允许属于多个分类，还是仅单一分类？影响数据模型与 UI 交互设计。
2. 播放速度记忆粒度：全局统一记忆还是按播客独立记忆？
3. 下载文件的默认存储路径与"迁移已下载文件"的交互方案（用户更改存储路径后，已下载文件是否自动迁移）。
4. 数据导出文件是否需要加密选项（例如导出文件本身设置密码保护，防止在同步盘中被他人读取）。
5. 搜索与发现模块（6.6节）具体接入哪个/哪些公开目录 API，是否需要用户自行申请并填入 API Key。
