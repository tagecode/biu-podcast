## 1. 品牌定位

Local-first / Offline-first 播客客户端。视觉温度：**温暖、沉静、可信赖**。琥珀色传达「本机数据、离线可用」的踏实感，而非云端 SaaS 的冷科技感。

### 1.1 品牌个性（三个关键词）

| 关键词                    | 含义                                                                          | 反例（不要做成什么样）               |
| ------------------------- | ----------------------------------------------------------------------------- | ------------------------------------ |
| **踏实（Grounded）**      | 暖色纸感背景、无渐变滥用、无玻璃拟态；数据在本机的信任感通过材质的"实"来传达  | 冷蓝紫渐变、玄幻发光边框、赛博朋克风 |
| **沉静（Calm）**          | 播客是背景陪伴媒介，UI 不抢注意力：低饱和中性色为主，琥珀仅用于关键动作与状态 | 高饱和多彩配色、频繁弹窗式提醒       |
| **可信赖（Trustworthy）** | 状态反馈明确（已听/已下载/离线/失败分色清晰），错误提示具体不含糊             | 模糊的"出错了"提示、隐藏用户数据去向 |

### 1.2 语气与文案原则（Voice & Tone）

- **说人话，不说系统话**：`"该订阅源已失效（404），请检查地址是否正确"`，而不是 `"Error: Request failed with status code 404"`。
- **离线不是失败态**：断网时的提示语气应是陈述事实＋给出仍可用的路径，例如 `"当前无网络，无法添加新订阅"` 而非 `"网络错误"`；已下载内容离线播放时**不展示任何网络相关提示**，做到"无感"。
- **危险操作说清楚后果**：取消订阅、清除数据等二次确认文案要说明"保留/删除了什么"，不用"确定吗？"这类空泛措辞。
- **中文界面为主语言**，标点使用中文全角（，。；：），英文/数字与中文之间加半角空格（如 `RSS Feed 地址`）；时间/时长格式走 `Intl.DateTimeFormat`/`Intl.NumberFormat` 本地化，不硬编码格式字符串。

### 2.2 深色主题（Dark）

深色主题不是"浅色主题反色"，而是独立校准的一套令牌，保证 `--amber-400` 在深色背景下作为强调色时对比度足够（对 `--night-bg` ≈ 8.4:1，对 `--night-surface` ≈ 7.3:1，均达 AAA）：

| Token                            | Hex       | 用途                                                                | 说明                                                    |
| -------------------------------- | --------- | ------------------------------------------------------------------- | ------------------------------------------------------- |
| `--night-bg`                     | `#1C1917` | 深色主题背景                                                        | 与浅色 `--ink` 同值，视觉呼应"暖黑"而非"冷黑"           |
| `--night-surface`                | `#292524` | 深色主题表面（卡片/列表面）                                         |                                                         |
| `--night-surface-raised`（新增） | `#332E2A` | 弹层、下拉菜单等更高层级表面，与 `--night-surface` 拉出可辨的层次差 |                                                         |
| `--night-ink`（新增）            | `#F2EDE4` | 深色主题主文字                                                      | 暖白，避免纯 `#FFFFFF` 在深色下的刺眼感                 |
| `--night-muted`（新增）          | `#A9A29B` | 深色主题次要文字                                                    |                                                         |
| `--night-line`（新增）           | `#40392F` | 深色主题分割线/边框                                                 |                                                         |
| `--amber-400`                    | `#E8A83A` | 深色主题主色：CTA、选中态、进度条填充                               | 深色下比 `--amber-600` 更适合做强调色，饱和度感知更稳定 |
| `--amber-300`（新增）            | `#F0C674` | 深色主题 hover 态（比 `--amber-400` 更亮一档）                      |                                                         |
| `--night-success`（新增）        | `#5FA971` | 深色主题成功态                                                      | 比浅色 `--success` 提亮，避免深底下饱和度不足显灰       |
| `--night-danger`（新增）         | `#E5484D` | 深色主题危险态                                                      |                                                         |
| `--night-offline`（新增）        | `#D08A3E` | 深色主题离线/警告 Banner                                            |                                                         |

> 落地方式：按 Arch.md §6.1，Tailwind v4 使用 `@theme` + CSS 变量定义令牌，`light`/`dark` 两套变量集合通过 `.dark` class 或 `prefers-color-scheme` 切换；本节的 Token 名即对应 CSS 变量名（去掉 `--` 前缀后可直接映射到 shadcn/ui 的 `--primary`/`--muted-foreground` 等语义变量，见第 8 章映射表）。

### 2.3 色彩使用铁律

1. **琥珀色只用于三类场景**：主要 CTA 背景、选中/激活状态指示、进度类反馈（下载进度条、播放进度条）。不用于大面积背景、不用于常规正文文字。
2. **状态色（success/danger/offline/warning）语义独占**：`--success` 只代表"已下载完成/操作成功"，不用作装饰色；`--danger` 只用于破坏性操作与失败态。
3. **深色主题不是简单反色**：任何新增语义色在深色下都要重新校验对比度，不能直接把浅色 hex 塞进深色变量集合。

## 3. 字体系统

| 用途                         | 字体族（按优先级）                                             | 说明                                                                        |
| ---------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 中文界面文字                 | `"PingFang SC", "Microsoft YaHei", "Noto Sans SC", sans-serif` | 三端系统默认中文无衬线字体优先，不内嵌字体文件（安装包体积/无字体授权成本） |
| 英文/数字界面文字            | `"Inter", -apple-system, "Segoe UI", Roboto, sans-serif`       | 中英混排时 `Inter` 与系统中文字体的数字对齐较自然                           |
| 等宽（时长/时间戳/文件大小） | `"SF Mono", "Cascadia Mono", "Consolas", monospace`            | 播放时间 `00:12:34`、下载速度等数字用等宽字体避免跳动                       |

### 3.1 字号阶梯（`--text-*`，4px 基准网格上取整）

| Token         | Size / Line-height | 用途                          |
| ------------- | ------------------ | ----------------------------- |
| `--text-xs`   | 12px / 16px        | 徽标文字、次要元数据          |
| `--text-sm`   | 13px / 18px        | 列表项次要文字、按钮小号      |
| `--text-base` | 14px / 20px        | 正文默认字号（播客/集数列表） |
| `--text-md`   | 16px / 24px        | 弹窗正文、表单标签            |
| `--text-lg`   | 18px / 26px        | 卡片标题、集数标题            |
| `--text-xl`   | 22px / 30px        | 播客详情页标题                |
| `--text-2xl`  | 28px / 36px        | 全屏播放器曲目标题            |

字重仅使用 `400`（正文）/`500`（强调、按钮）/`600`（标题）三档，不引入 `300`/`700` 造成中文字体渲染不一致的问题（多数中文字体没有真 Light/Bold 字重，会被系统模拟加粗，边缘发虚）。

## 4. 间距与布局网格

- 基准网格 **4px**，Tailwind 默认间距刻度（`1`=4px … `4`=16px … `6`=24px）直接使用，不额外定义奇数间距。
- 常用语义间距：列表项内边距 `12px 16px`、卡片内边距 `16px`、弹窗内边距 `24px`、页面主内容区左右留白 `24px`（窗口宽度 <960px 时降为 `16px`，对应 PRD §7.4 高 DPI/响应式布局要求）。
- 迷你播放器高度固定 `72px`，常驻页面底部，内容区滚动时不被遮挡（`padding-bottom: 72px` 由布局层统一处理，业务组件不各自 hack）。

## 5. 圆角与阴影

| Token           | 值    | 用途                                 |
| --------------- | ----- | ------------------------------------ |
| `--radius-sm`   | 6px   | 徽标、Chip、小号按钮                 |
| `--radius-md`   | 10px  | 卡片、输入框、常规按钮               |
| `--radius-lg`   | 16px  | 弹窗、大卡片（播客封面容器）         |
| `--radius-full` | 999px | 头像/封面圆形裁切、播放/暂停圆形按钮 |

阴影遵循"低饱和、暖色投影"而非默认纯黑阴影，避免冷调违和：

| Token         | 值                                 | 用途                                   |
| ------------- | ---------------------------------- | -------------------------------------- |
| `--shadow-sm` | `0 1px 2px rgb(28 25 23 / 0.06)`   | 列表项 hover、输入框 focus 外的微阴影  |
| `--shadow-md` | `0 4px 12px rgb(28 25 23 / 0.10)`  | 卡片悬浮、下拉菜单                     |
| `--shadow-lg` | `0 12px 32px rgb(28 25 23 / 0.16)` | 弹窗（Dialog）、全屏播放器展开动画终态 |

深色主题下阴影改用更低不透明度但更大扩散（暖黑背景下传统阴影几乎不可见）：`--shadow-md-dark: 0 4px 16px rgb(0 0 0 / 0.4)`。

## 6. 图标系统

- 统一使用 **lucide-react**（已在 Arch.md 技术选型中确定），不混用其他图标库，保证线宽/圆角风格一致。
- 描边宽度固定 `1.75`（lucide 默认 `2` 在 14~16px 小尺寸下略粗，中文界面里与文字混排时视觉偏重，统一调为 `1.75`）。
- 尺寸令牌：`--icon-sm` 16px（列表项内状态图标）、`--icon-md` 20px（按钮内图标、工具栏）、`--icon-lg` 24px（播放器主控制按钮）、`--icon-xl` 40px（全屏播放器播放/暂停主按钮）。
- 图标颜色跟随文字色继承（`currentColor`），不单独设定图标专属色板，保证深浅主题切换时无需额外适配。
- 语义图标固定映射（避免不同开发者各自选择造成不一致）：

  | 语义           | lucide 图标                                |
  | -------------- | ------------------------------------------ |
  | 播放 / 暂停    | `Play` / `Pause`                           |
  | 已下载         | `CheckCircle2`（用 `--success` 着色）      |
  | 下载中         | `Download`（配合环形进度）                 |
  | 下载失败       | `AlertCircle`（用 `--danger` 着色）        |
  | 离线           | `WifiOff`（用 `--offline` 着色）           |
  | 未听（点状态） | 实心圆点 8px，`--amber-600`                |
  | 已听           | 不显示图标（默认态即"已读"，避免过度装饰） |

## 7. 核心组件规范

以下为 shadcn/ui 组件的主题化取值建议，落地时对应 T0.1（引入 Tailwind + shadcn/ui）任务：

### 7.1 按钮（Button）

| 状态                              | 背景                         | 文字          | 说明                                                     |
| --------------------------------- | ---------------------------- | ------------- | -------------------------------------------------------- |
| Default（主按钮）                 | `--amber-600`                | `--ink`       |                                                          |
| Hover                             | `--amber-500`                | `--ink`       | 与 default 共用文字色，避免跳变                          |
| Active/Pressed                    | `--amber-700`                | `#FFFFFF`     | 唯一切换文字色的状态，因其停留时间短（点击瞬间），可接受 |
| Disabled                          | `--line`                     | `--muted-700` | 不透明度不做额外调整，直接换色以保证对比度可控           |
| 危险按钮（取消订阅/清除数据）     | `--danger`                   | `#FFFFFF`     |                                                          |
| 次要按钮（Secondary）             | `--surface` + `--line` 边框  | `--ink`       |                                                          |
| 幽灵按钮（Ghost，工具栏图标按钮） | 透明，hover 时 `--amber-100` | `--ink`       |                                                          |

按钮文字最小 14px，字重 `500`；主按钮/危险按钮不使用全透明或渐变背景。

### 7.2 输入框（Input / Textarea，用于订阅 URL 输入等）

- 默认边框 `--line`，focus 态边框 `--amber-600` + `0 0 0 3px rgb(198 124 20 / 0.15)` 的外发光（不用默认蓝色 focus ring，需在 shadcn/ui 主题变量中覆盖 `--ring`）。
- 错误态（如 T3.2 的 URL 格式校验失败）边框改为 `--danger`，下方错误文案 `--text-xs` + `--danger`，图标 `AlertCircle`。

### 7.3 状态徽标（Badge，用于集数列表"已听/未听/已下载"组合状态，对应 Mvp T4.2）

四种组合各自的视觉规则（**已听/未听** 与 **已下载/未下载** 是两组独立徽标，不合并成一个）：

| 已听状态 | 已下载状态 | 呈现                                                                     |
| -------- | ---------- | ------------------------------------------------------------------------ |
| 未听     | 已下载     | 标题旁 8px 实心圆点（`--amber-600`）+ 行尾 `CheckCircle2`（`--success`） |
| 未听     | 未下载     | 仅 8px 实心圆点（`--amber-600`），无下载图标                             |
| 已听     | 已下载     | 无圆点 + 行尾 `CheckCircle2`（`--success`），标题文字色降为 `--muted`    |
| 已听     | 未下载     | 无圆点、无下载图标，标题文字色降为 `--muted`                             |

下载中状态额外覆盖：显示环形进度（`--amber-600` 描边，`--line` 底色），不与"已听/未听"圆点同时出现在同一位置（下载中时圆点临时让位给进度环，避免视觉堆叠）。

### 7.4 播放器（迷你播放器 + 全屏播放器）

- 进度条轨道 `--line`，已播放部分 `--amber-600`（深色主题 `--amber-400`），拖拽手柄为 `--radius-full` 圆形，默认隐藏，hover/拖拽时显现，直径 12px。
- 迷你播放器背景 `--surface`（深色 `--night-surface`），顶部 `1px` 分割线用 `--line`，不用阴影分隔（阴影在暖色背景下容易显脏）。
- 全屏播放器背景可用封面主色提取做轻量渐变底（P1 可选增强），MVP 阶段直接用 `--paper`/`--night-bg` 纯色即可，不做取色算法这一层复杂度。

### 7.5 离线 / 警告 Banner

- 顶部条形通栏，背景 `--offline`，白色文字，左侧 `WifiOff` 图标，高度 40px，不可通过点击关闭（因为它反映的是真实网络状态，关闭后用户会忘记自己处于离线态）；网络恢复后自动消失，无需用户操作。
- 存储空间不足预警复用同一视觉规则，图标换为 `AlertTriangle`，文案走 `--warning` 语义（当前与 `--offline` 同色值）。

### 7.6 Toast / 通知

- 背景 `--surface`，左侧 4px 色条按语义着色（成功 `--success`/失败 `--danger`/信息 `--amber-600`），阴影 `--shadow-md`，圆角 `--radius-md`。
- 下载完成、新集数通知等非阻塞信息走 Toast；破坏性操作确认走 Dialog（Radix `AlertDialog`），不要用 Toast 承载需要用户决策的内容。

### 7.7 空状态 / 加载态（对应 Mvp T3.6）

- 空状态：图标（`--muted` 着色的线性插图，非彩色插画，避免与品牌琥珀色抢视觉）+ 一句引导文案 + 一个主按钮，不使用大幅插画降低首屏加载成本。
- 加载态：使用 shadcn/ui `Skeleton`，背景 `--line` 的 40% 不透明度，呼吸动画周期 1.5s，不用旋转 Spinner 作为列表级加载指示（旋转图标更适合按钮内的小范围加载）。

## 8. shadcn/ui 语义变量映射

## 9. 动效原则

- 时长：微交互（hover/按压）`120ms`，组件展开/收起（Dialog/下拉菜单）`180ms`，页面级切换（订阅列表→详情页）`220ms`，统一用 `ease-out` 进入、`ease-in` 退出，不使用弹性/回弹曲线（与"沉静"品牌个性冲突）。
- 播放/暂停按钮点击有 `scale(0.96)` 的按压反馈，其余按钮不做位移/缩放，仅变色，减少非必要动效。
- 尊重系统级"减少动态效果"设置（`prefers-reduced-motion`），命中时全局动效时长归零或降级为透明度渐变，不做位移/缩放类动画。

## 10. 无障碍检查清单

对应 Prd.md §6.8 无障碍需求，视觉规范层面需保证：

- [ ] 所有正文文字对比度 ≥ 4.5:1（本文档第 2 章已标注各色对的实测值）
- [ ] 图标类交互元素对比度 ≥ 3:1，且不作为唯一状态区分手段（已听/未听除了圆点还应有文字色差异，兼容色觉障碍用户）
- [ ] Focus 态使用统一的 `--ring` 外发光，不移除默认 focus 样式（`outline: none` 全局禁止裸用）
- [ ] 深色/浅色主题切换后，所有语义色重新走过第 2 章的对比度校验，不直接复用另一主题的 hex
