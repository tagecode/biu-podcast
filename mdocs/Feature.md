## 设计原则

- **Feature-first**: 以用户场景驱动功能拆分，每个功能独立可交付、可测试
- **Offline-first**: 所有核心功能在离线状态下可用，网络仅用于同步和刷新
- **Local-first**: 数据优先存储在本机，用户完全拥有自己的订阅、播放记录和下载内容
- **Desktop-only**: 仅面向桌面端（Windows / Linux / macOS），不提供移动端（Android / iOS）与浏览器 Web 端

## 10. 技术架构要点

### 10.1 架构模式

- [x] Feature-first 目录结构（按功能模块组织代码）
- [x] 状态管理方案（如 Zustand / Redux Toolkit / Jotai，按渲染进程规模选定）
- [x] Repository 模式隔离数据源（渲染进程通过 IPC 调用主进程封装的数据访问层，不直接触碰 Node/文件系统 API）
- [x] 主进程 / 渲染进程 / Preload 三层职责清晰分层，契合 Electron 安全模型

### 10.2 核心依赖（规划）

> 项目基于 Electron + Vite + React + TypeScript（见 `package.json`），以下为对应桌面端技术选型，替代早期误写的 Flutter 生态依赖。

- [x] 音频播放：HTML5 `<audio>` / `howler.js`（渲染进程播放）+ 主进程绑定系统媒体控制（Windows SMTC / macOS Now Playing / Linux MPRIS，可能需原生模块或第三方封装）（HTML5 audio 已交付；系统媒体控件未接）
- [x] `better-sqlite3` 或 `drizzle-orm`（基于 SQLite）— 本地数据库
- [x] `electron-store` — 轻量本地配置/缓存
- [x] `axios` / 原生 `fetch`（Node 18+/undici）— HTTP 请求
- [x] `rss-parser` — RSS Feed 解析
- [ ] 分享：Electron 无跨平台原生分享 API，需自行实现（复制链接 / macOS `NSSharingService` 桥接 / 系统分享面板降级方案）
- [x] `app.getPath()`（Electron 内置）— 文件路径管理，替代 `path_provider`
- [x] Electron 内置 `BrowserWindow` / `Tray` — 窗口与系统托盘管理
- [x] Electron 内置 `globalShortcut` — 全局快捷键
- [x] Electron 内置 `Notification` — 本地系统通知
- [x] `electron-updater` — 自动更新（已引入，对应 9.2）
- [x] i18n 方案（如 `i18next` / `react-i18next`）— 多语言支持（对应 8.5）

### 10.3 离线能力

- [x] 所有 UI 在无网络时可正常访问
- [x] 已下载内容可离线播放
- [ ] 本地搜索不依赖网络（仅有订阅列表标题搜索；无集数全文搜索）
- [ ] 网络恢复后自动同步待办操作
