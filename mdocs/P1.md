## 1. P1 范围与依赖图

### 1.1 范围边界

P1 = PRD §5.2（正式版）中尚未实现的功能，按用户价值与依赖关系分阶段：

- **P1-A 收听体验增强**（播放器相关，用户最直接感知）
- **P1-B 数据组织**（播放列表 / 笔记，Local-first 数据域扩充）
- **P1-C 桌面集成**（托盘 / 系统媒体控件 / 通知 / 快捷键 / 深链接）
- **P1-D 平台与外观**（深色模式 / 多语言 / 字体调节 / 自动更新 / 关于页）
- **P1-E 订阅增强**（OPML / 暂停订阅 / 自动刷新 / 新集通知）
- **P1-F 设置与管理**（存储空间 / 自动清理 / 清除数据 / 诊断日志）

### 1.2 依赖图

```
P1-E 订阅增强（OPML / 暂停 / 自动刷新）
  └─▶ P1-B 数据组织（播放列表复用订阅数据模型）
        └─▶ P1-A 收听体验（变速 / 睡眠定时器依赖播放器状态机）
             └─▶ P1-C 桌面集成（系统媒体控件读取播放状态）
P1-D 平台外观（深色 / 多语言 全局改动，可与 A/B/C 并行）
P1-F 设置管理（存储 / 清理 / 日志 依赖下载子系统）
```

**关键路径**：P1-E → P1-B → P1-A → P1-C。P1-D 与 P1-F 可并行。

## 3. 任务详情

### Epic E10：收听体验增强

#### P1-1 变速播放（0.5x ~ 3.0x）

- **依赖**：无　**规模**：M
- **描述**：播放器支持 `playbackRate` 调节（0.5–3.0，步长 0.1）。`usePlaybackStore` 增加 `playbackRate` 状态 + `setPlaybackRate`；全屏播放器提供速率选择控件（Shadcn `Select`，复用 `src/renderer/src/components/ui/select.tsx`）；速率持久化到 `electron-store`（`playbackRateDefault`）。
- **验收标准**：
  - Given 用户将速率调到 1.5x，When 播放，Then `<audio>.playbackRate === 1.5`，音调不变（`preservesPitch` 默认 true）。
  - Given 用户设置 2.0x 后重启应用，When 播放新集，Then 默认速率为 2.0x（记忆上次选择）。
- **测试要求**：单元测试（store 状态转换 + 持久化读写）；组件测试（速率选择控件交互）。
- **交付物**：`usePlaybackStore.ts` 扩展、全屏播放器速率控件、`store.test.ts` 补充。

#### P1-2 睡眠定时器

- **依赖**：无　**规模**：S
- **描述**：全屏播放器提供定时器（10s/30s/1m/5m/15m/30m/60m），倒计时结束自动暂停播放；定时期间显示剩余时间，可取消。
- **验收标准**：
  - Given 设置 5 分钟定时器，When 倒计时归零，Then 播放自动暂停，`isPlaying === false`，进度保留。
  - Given 定时器运行中，When 用户取消，Then 定时器移除，播放不受影响。
- **测试要求**：单元测试（定时器逻辑用假时钟/`vi.useFakeTimers`）。
- **交付物**：`usePlaybackStore.ts`（`sleepTimer` 状态 + `setSleepTimer`）、播放器定时器 UI。

#### P1-3 全屏播放器键盘快捷键（空格/方向键）

- **依赖**：无　**规模**：S
- **描述**：全屏播放器聚焦时，空格键播放/暂停，←/→ 调整进度（±10s），↑/↓ 调整音量。仅在播放器视图激活时生效，不污染全局。
- **验收标准**：
  - Given 全屏播放器打开且播放中，When 按空格，Then 暂停；再按恢复。
  - Given 播放中，When 按 →，Then 进度 +10s（不超过总时长）。
- **测试要求**：组件测试（模拟 keydown 事件断言 store 调用）。
- **交付物**：全屏播放器键盘处理（`FullScreenPlayer.tsx` 补充）。

#### P1-4 播放队列（当前播放序列 + 循环模式）

- **依赖**：P1-1　**规模**：L
- **描述**：播放器维护"当前播放序列"（独立于持久化播放列表）：从集数列表/详情"加入队列"；支持单曲循环/列表循环/随机播放三种模式；`next`/`previous` 基于队列而非仅相邻集。
- **验收标准**：
  - Given 队列有 [A, B, C]，当前播放 B 且列表循环，When 点击"下一集"，Then 播放 C；到 C 后再点，Then 回到 A。
  - Given 随机模式开启，When 每次切集，Then 序列顺序随机且不重复（洗牌算法）。
- **测试要求**：单元测试（队列状态机 + 洗牌/循环逻辑，纯函数）。
- **交付物**：`usePlaybackStore.ts`（`queue`、`queueMode` 状态 + 动作）、`lib/queue.ts` 纯函数及测试。

#### P1-5 播放器布局偏好（迷你/全屏默认）

- **依赖**：无　**规模**：S
- **描述**：设置中可选"默认打开全屏播放器"或"始终迷你"，持久化到 `electron-store`。
- **验收标准**：
  - Given 用户设为"默认全屏"，When 点击播放某集，Then 播放器直接以全屏视图打开。
- **测试要求**：单元测试（store 读取偏好决定初始 `view`）。
- **交付物**：设置项 + `usePlaybackStore` 初始化逻辑。

#### P1-6 播放速度记忆粒度（全局/按播客）

- **依赖**：P1-1　**规模**：S
- **描述**：开放问题 PRD §14.2 定案——默认**全局记忆**；后续按播客独立记忆作为增强（本次不做）。
- **验收标准**：与 P1-1 一致（全局记忆覆盖）。
- **测试要求**：并入 P1-1。
- **交付物**：文档说明（在 P1.md 开放问题记录）。

### Epic E11：数据组织

#### P1-7 播放列表数据模型与 CRUD

- **依赖**：无　**规模**：L
- **描述**：新增 `playlists` 与 `playlist_items` 表（PRD §8 数据模型）；`PlaylistRepository`（建/删/改名）；IPC：`playlist:{create,list,rename,delete}`；渲染进程播放列表页（列表 + 集数项）。
- **验收标准**：
  - Given 创建一个名为"通勤"的播放列表，When 查询列表，Then 返回含该播放列表，集数为空。
  - Given 删除一个播放列表，When 查询，Then 不存在，且关联的 playlist_items 级联删除。
- **测试要求**：集成测试（Repository CRUD + 迁移建表）；组件测试（播放列表页）。
- **交付物**：`src/main/infra/db/schema.ts` 扩展、`playlist.repository.ts`、`src/shared/ipc-contract.ts` 扩展、播放列表 UI。

#### P1-8 往播放列表添加/移除集数

- **依赖**：P1-7　**规模**：M
- **描述**：集数列表/详情提供"添加到播放列表"操作（弹出已建播放列表选择）；播放列表内可移除集数；集数可重复添加（同一集可出现在多个播放列表）。
- **验收标准**：
  - Given 集数 X 未在任何播放列表，When 添加到"通勤"，Then 该列表含 X，且列表页刷新可见。
  - Given 从"通勤"移除 X，When 查询，Then X 不在该列表，但 X 本身未删除。
- **测试要求**：集成测试（关联 CRUD + 事务性）；E2E（添加→查看→移除完整旅程）。
- **交付物**：`playlist.repository.ts` 扩展、`playlist:{addItem,removeItem}` IPC、UI 入口。

#### P1-9 播放列表拖拽排序

- **依赖**：P1-8　**规模**：M
- **描述**：播放列表内集数支持拖拽排序，持久化 `sort_order`。需引入拖拽库（如 `@dnd-kit/core`）或手写 HTML5 DnD。
- **验收标准**：
  - Given 播放列表 [A, B, C]，When 将 C 拖到最前，Then 顺序变为 [C, A, B] 并持久化。
- **测试要求**：组件测试（拖拽交互 + 排序结果）；集成测试（`sort_order` 落库）。
- **交付物**：拖拽依赖、`playlist.repository.ts`（`reorder` 方法）、列表拖拽 UI。

#### P1-10 时间戳笔记（数据模型 + 记录）

- **依赖**：无　**规模**：M
- **描述**：新增 `notes` 表（PRD §8：episodeId, timestampSec, content, createdAt）；播放中（或集数详情）添加时间戳笔记；`NoteRepository`；IPC：`note:{create,listByEpisode,delete}`。
- **验收标准**：
  - Given 播放到 12:34 时添加笔记"重点"，When 查询该集笔记，Then 返回 `{timestampSec: 754, content: "重点"}`。
- **测试要求**：集成测试（笔记 CRUD + 时间戳换算）；组件测试（笔记输入框）。
- **交付物**：`notes` 表、`note.repository.ts`、笔记 IPC、播放器笔记入口。

#### P1-11 笔记列表查看与导出

- **依赖**：P1-10　**规模**：S
- **描述**：笔记列表页（按集分组展示）；导出为 Markdown/纯文本文件（经主进程文件对话框）。
- **验收标准**：
  - Given 某播客有 3 条笔记，When 查看笔记列表，Then 按时间倒序展示，含集标题与时间戳。
  - Given 点击导出，Then 生成 Markdown 文件，内容含全部笔记。
- **测试要求**：组件测试（列表渲染）；集成测试（导出文件内容）。
- **交付物**：笔记列表页、`note:export` IPC（主进程写文件）。

### Epic E12：桌面集成

#### P1-12 系统托盘

- **依赖**：E10　**规模**：M
- **描述**：托盘图标 + 右键菜单（播放/暂停、上一集、下一集、显示主窗口、退出）；关闭窗口行为可选"最小化到托盘"（设置项）；托盘图标可反映播放态（可先简化）。

#### P1-13 系统媒体控件集成（SMTC / Now Playing / MPRIS）

- **依赖**：E10（读取播放状态）　**规模**：L
- **描述**：Electron 无跨平台原生媒体会话 API（electron/electron#32177 仍未关闭）。**Spike 已定案**（见 [`P1-13-Spike.md`](./P1-13-Spike.md)）：不引入跨平台第三方库——`electron-media-service` 经调研确认已废弃（win/linux 从未实现，npm 停留 0.2.2/2017）；采用**分层适配器**：Linux 用纯 JS `mpris-service`、Windows 自研 `.NET` 伴生进程桥接 SMTC、macOS 自研 Node-API 模块封装 MPRemoteCommandCenter（对应 PRD §13 风险项）。
- **验收标准**：
  - Given 播放某集，When 查看系统媒体中心（Windows 媒体播放浮动窗 / macOS 控制中心 / Linux MPRIS），Then 显示播客/集标题，可播放/暂停/切集。
- **测试要求**：三平台分别人工验收 + 主进程状态同步单元测试（假 adapter）。Spike 结论见 `P1-13-Spike.md`。
- **交付物**：`mdocs/P1-13-Spike.md`（已产出）、`src/main/infra/media-session/`（适配器接口 + 各平台实现 + noop 降级）、`playback.service.ts` 状态广播。
- **实现拆解**（按 Spike §6 顺序，复杂度递增）：
  1. **Linux MPRIS**（S）—— `linux-mpris.ts` 包装 `mpris-service`，纯 JS 无编译，先行验证接口；
  2. **Windows SMTC**（M）—— `.NET` 伴生进程 + stdio/JSON 桥接 `win-smtc.ts`，随 NSIS 打包；
  3. **macOS Now Playing**（L）—— Node-API 原生模块 + `mac-nowplaying.ts`，三端 CI 分别构建；短期无 mac 用户可标「可选增强」延后，用 noop 降级。

#### P1-14 系统通知（新集/下载完成）

- **依赖**：无　**规模**：S
- **描述**：新集数出现（手动/自动刷新后）与下载完成时触发系统通知；设置中可关闭（`notificationPrefs`）。
- **验收标准**：
  - Given 刷新后发现 2 集新集，When 刷新完成，Then 触发一条系统通知（"发现 2 集新内容"）。
  - Given 设置关闭通知，When 上述场景，Then 不触发。
- **测试要求**：主进程单元测试（通知触发逻辑，mock `Notification`）；组件测试（设置开关）。
- **交付物**：`src/main/infra/notification/index.ts`、设置项、service 接线。

#### P1-15 全局快捷键

- **依赖**：无　**规模**：M
- **描述**：`globalShortcut` 注册系统级快捷键（默认：媒体键 Play/Pause/Next/Prev 映射到播放器；可自定义组合键，先提供默认值）。应用未聚焦时也可用。当前已实现：媒体键 + 软件组合键候选链（`Ctrl+Alt+P/Space` 播放暂停、`Ctrl+Alt+N` 下一集、`Ctrl+Alt+B` 上一集），每个命令多候选自动降级，冲突不致死命令；注册结果打印日志。
- **验收标准**：
  - Given 应用在后台，When 按全局播放/暂停快捷键，Then 播放状态切换。
  - Given 某组合键被其他应用占用，When 注册，Then 自动落到下一候选键，命令仍可用（非致命）。
- **测试要求**：主进程单元测试（注册/注销生命周期 + 快捷键→动作映射）；无头环境无法实测系统级按键，以单元测试为准。
- **交付物**：`src/main/infra/shortcuts/index.ts`、`main/index.ts` 接线。

#### P1-15b 全局快捷键自定义（偏好设置）

- **依赖**：P1-15（快捷键基础设施）、settings 持久化　**规模**：L
- **描述**：设置页新增「快捷键」区块，列出每个播放命令（播放/暂停、上一集、下一集）与当前绑定的快捷键；用户点击后进入**录制模式**（按键捕获组合键，替换/解除绑定）；持久化到 `electron-store`；启动时按用户配置注册，未配置项回落默认键。
- **验收标准**：
  - Given 用户将"播放/暂停"改为 `Ctrl+Shift+Space`，When 保存并重启，Then 该组合键生效，且与默认键不冲突。
  - Given 用户为两个命令设置同一组合键，When 保存，Then 提示冲突并拒绝（不允许重复绑定）。
  - Given 用户录制的组合键被其他应用占用，When 注册，Then 提示"该快捷键被占用"并回落上一配置。
- **测试要求**：主进程单元测试（注册结果→设置读写、冲突检测、占用回退）；组件测试（录制模式 UI 与按键捕获）；E2E（设置页改键→重启后生效）。
- **交付物**：`src/main/infra/shortcuts/index.ts`（读配置）、`src/shared/ipc-contract.ts`（shortcut 读写通道）、`src/renderer/src/features/settings/`（快捷键设置区块）、录制交互组件。

#### P1-16 深链接协议（biu-podcast://）

- **依赖**：无　**规模**：M
- **描述**：注册 `biu-podcast://` 协议（Windows 注册表 / macOS `CFBundleURLTypes` / Linux desktop entry `MimeType`）；处理外部唤起：`biu-podcast://subscribe?url=...` 跳转订阅流程、`biu-podcast://play/<episodeId>` 播放指定集。
- **验收标准**：

- **依赖**：无　**规模**：L
- **描述**：解析标准 OPML 1.0/2.0 文件（含 `<outline>` 嵌套结构），批量导入订阅；逐条失败不影响其余（复用 `add()` 逻辑，按 feedUrl 去重）；保留分类分组（若 P1-24 分类已实现，则映射；否则仅导入订阅平铺）。
- **验收标准**：
  - Given 导入含 5 个 outline 的 OPML，When 执行导入，Then 新增 5 个订阅（重复 URL 跳过），不产生脏数据。

- **测试要求**：集成测试（OPML 解析 + 批量入库 + 部分失败容错）；E2E（导入文件→订阅列表增长）。

- **验收标准**：

- **测试要求**：集成测试（导出文件结构校验）。

#### P1-24 暂停/恢复订阅

- **描述**：schema 已有 `isPaused`，补齐 UI 流程：详情页"暂停订阅"按钮（暂停后不拉取更新，保留数据）；订阅列表暂停状态标识；恢复。
- **验收标准**：
  - Given 暂停某订阅，When 触发自动/手动刷新，Then 该订阅被跳过不请求网络，且列表有暂停标识。
  - Given 恢复，When 刷新，Then 恢复正常拉取。
- **测试要求**：集成测试（`isPaused` 过滤刷新）；组件测试（暂停/恢复按钮 + 状态标识）。
- **交付物**：`subscription.service.ts`（暂停过滤）、详情页按钮、列表标识。

#### P1-25 自动刷新间隔

- **依赖**：无　**规模**：M
- **描述**：设置中可选自动刷新间隔（30min/1h/6h/手动）；主进程定时器按间隔刷新全部订阅（后台静默，不打断播放）；遵循暂停订阅跳过。
- **验收标准**：
  - Given 设置 1 小时自动刷新，When 到达触发点，Then 后台刷新全部活跃订阅，新集通知（若开启）触发。
  - Given 设为手动，When 无手动操作，Then 不自动请求网络。
- **测试要求**：主进程单元测试（调度器逻辑用假时钟）；集成测试（刷新结果落库）。
- **交付物**：`src/main/features/subscription/auto-refresh.ts`、设置项。

- **描述**：设置"保留最近 N 天/N 集"，超出自动清理最旧的已下载且已听内容（删除文件 + 修正状态）；清理前可预览待删项。
- **验收标准**：
  - Given 保留最近 3 集已下载且已听，When 触发清理，Then 更早的已下载已听集被删除文件并标记未下载，未听/最近集保留。
- **测试要求**：集成测试（清理选择逻辑 + 文件删除 + 状态修正）。

#### P1-29 清除缓存 / 清除全部数据

- **依赖**：无　**规模**：M
- **描述**：两级操作：①"仅清缓存"（图片/临时文件，不动用户数据）；②"清除全部数据"（二次确认，清库 + 文件 + 设置）。均经确认弹窗。
- **验收标准**：
  - Given 用户执行"清除全部数据"，When 二次确认，Then 数据库重置、下载文件删除、应用回到首次使用状态。
  - Given 用户执行"仅清缓存"，When 完成，Then 订阅/进度/下载记录保留。
- **测试要求**：集成测试（两级清理的数据库/文件最终状态）；E2E（清除→空状态）。
- **交付物**：`cleanup.service.ts` 扩展、设置清理区、二次确认 UI。

#### P1-30 诊断日志（可关闭）

- **依赖**：无　**规模**：S
- **描述**：主进程 + 渲染进程关键事件（Feed 拉取、下载、播放错误）写日志文件（`userData/logs/`）；设置可关闭；提供"一键导出诊断信息"（日志 + 环境信息，供反馈）。
- **验收标准**：
  - Given 日志开启，When 发生一次 Feed 拉取失败，Then 日志文件记录失败原因与时间。
  - Given 设置关闭日志，When 再发生事件，Then 不再写入。
- **测试要求**：主进程单元测试（日志写入/开关）；集成测试（诊断导出内容）。
- **交付物**：`src/main/infra/logger/index.ts`、设置开关、诊断导出 IPC。
